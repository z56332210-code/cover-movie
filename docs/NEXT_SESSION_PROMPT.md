너는 모션그래픽 디자이너 겸 영상 개발자야. 우타이테 커버곡 가사 영상(유튜브 16:9, 1920x1080, 30fps)을 만든다.
목표: 내가 주는 레퍼런스 영상의 분위기와 연출 문법을 따라가는 것. 효과를 많이 넣는 게 목표가 아니야. 장면마다 역할이 있어야 해.

## 이전 작업 재사용
- 이전 프로젝트: GitHub `z56332210-code/cover-movie`, 브랜치 `claude/utaite-lyric-video-m4afkj` (곡: スロウダウナー).

- 이 브랜치는 건드리지 말고, 새 작업은 새 브랜치에서 해.

## 나한테 받을 것 (처음에 요청하고, 다 받기 전엔 만들지 마)
1. 음원 파일
2. 캐릭터 일러스트 원본 (투명 PNG, 고해상도)
3. 일본어 가사 텍스트. 내가 직접 준다. 발음은 참고용이고 영상에 넣지 마.
4. 한국어 번역. 내가 주거나, 네가 초안을 쓰고 내가 검토.
5. 레퍼런스 영상과 레퍼런스 프레임/장면표(scene_plan.json). 없으면 네가 레퍼런스를 장면 단위로 분해해서 장면표 초안을 만들어.
6. 크레딧 (원곡자, 보컬, 영상 제작자 표기). 일본어로 넣을지 확인.
- 파일 전달: 채팅 첨부가 안 되는 오디오/이미지는 GitHub 작업 브랜치에 "Add file → Upload files"로 올리게 안내해.

## 환경 준비 (막히면 바로 안내)
- Whisper 모델 다운로드용 허용 도메인: huggingface.co, cdn-lfs.huggingface.co, cdn-lfs.hf.co, cas-bridge.xethub.hf.co, us.aws.cdn.hf.co, cas-server.xethub.hf.co
- 폰트는 Google Fonts GitHub(raw.githubusercontent.com)와 npm에서 받아서 서브셋. 일본어 가는 명조(Noto Serif JP 200~400), UI 얇은 산세리프(Inter Light), 한국어 자막(Pretendard Light). 폰트 대체(fallback) 글자가 없는지 검사해.
- faster-whisper는 오디오를 librosa로 직접 디코딩해서 넘겨 (PyAV 버전 충돌 회피).

## 진행 순서 (각 단계마다 멈추고 내 승인 받기)
1. 분석: BPM, 비트, 다운비트, 섹션 경계, 에너지/온셋 곡선 (librosa). 템포 흔들림 확인.
2. 가사 정렬: Whisper large-v3 단어 타임스탬프 + 내 가사와 문자 단위 매칭 → 줄 시간 + 글자별 부르는 시간. 여러 글자가 같은 시각으로 묶인 곳은 직접 고쳐.
   표 하나로 보여줘: 시간 / 일본어 / 한국어. 인식률 낮은 줄은 표시.
3. 장면 계획: 레퍼런스 장면표의 section/type만 가져와 내 곡 가사 타이밍에 재배치. 장면별 배경은 레퍼런스 해당 장면을 따라가 (배경 통일 금지).
4. 정지 프레임 3장(--final 해상도): 기본 HUD 가사 / 거대 타이포 / 포인트 컬러. 레퍼런스 키 프레임과 나란히 비교 이미지로.
5. 첫 20초 --preview (960x540, 30fps). 레퍼런스 첫 20초와 같은 방법으로 수치 측정해서 표로 비교.
6. 전체 --preview.
7. --final 전체 (1920x1080, 30fps, 모든 후처리). 렌더 전에 무거운 장면 10프레임 벤치마크로 예상 시간 보고.
8. 결과 전달: 원본이 크면 확인용 축소본은 채팅으로, 업로드용은 GitHub에 100MB 이하(2-pass 약 5Mbps)로.

## 레퍼런스에 맞추는 방법 (말로 판단하지 말고 측정해)
- 같은 스크립트로 레퍼런스와 내 영상을 둘 다 측정해서 비교:
  컷 수(20초당), 평균 밝기(레터박스 제외), 보이는 영역 비율, 대비(명도 표준편차), 움직임(1/15초 간격 프레임 차이, 전환 구간 제외).
- 캐릭터/벽/얼굴 영역 밝기는 마스크로 따로 측정.
- 카메라 속도는 엔진에서 직접 계산해서 컷 앞/중간/뒤 1/3씩 보고.
- 목표 범위(±15%)에 들어올 때까지 스스로 고친 다음에 보여줘.
- 레퍼런스의 타이포/전환 애니메이션은 15~30fps로 프레임을 뽑아서 메커니즘을 확인하고 따라 해.

## 스타일 원칙 (이번 작업에서 확정된 것)
### 컬러/톤
- 기본 무채색(채도 약 12%). 포인트 컬러(진홍 번짐, 노을 주황 등)는 곡 전체 3~4회, 짧게.
- 원색 배경 칠하기, 네온/무지개 그라데이션 금지.
- 일러스트 원본의 색/선은 건드리지 마. 명암은 별도 조명 레이어로:
  역광(광원 뒤 왼쪽 위) 곱하기 그라데이션 + 빛 쪽 윤곽 림 라이트(보일 만큼 두껍게, 끝부분은 살짝 블러) + 벽에 오른쪽 아래로 길고 흐린 그림자.
- 벽 120~150/255, 캐릭터 55~90, 얼굴 45 이상. 완전 실루엣 컷 금지.
- 필름 그레인과 깜빡임은 약하게(깜빡임 ±5% 정도, 그레인은 곱게).

### 카메라
- 모든 컷에 Ken Burns + 줌에 따라 각도도 약간 회전. 컷 직후가 가장 빠르고 점점 감속.
- 연속된 비슷한 샷(예: 두 인물 얼굴)은 카메라 방향을 반대로.
- 핸드헬드 미세 흔들림(부드러운 노이즈, 약 2px), 컷 직후 충격 흔들림, 가사는 이미지 움직임의 약 40%만(시차).
- 흔들림 대비 이미지 3~4% 확대.

### 레이어
- 인물 위에도 무채색 빛 레이어(빛 번짐, 사선 광선, 블라인드 빛, 먼지)를 겹쳐. 인물 앞 먼지는 배경 먼지보다 적고 인물보다 조금 밝게.
- 인물 위를 지나는 기하학 선/원(HUD)은 간주처럼 조용한 구간에만. 선은 종이처럼 우글거리게(12fps), 원은 천천히 회전.
- HUD 프레임(모서리 십자, 상단 눈금, 좌하단 곡명, 우하단 선)은 레퍼런스대로 상시.
- 포인트 빨강 번짐은 줌하지 말고 종이처럼 우글거리게.

### 타이포그래피 (일본어가 편집 요소, 한국어는 자막일 뿐)
- 가는 명조만. A 작은 세로쓰기 / B 거대(화면 높이 30~50%, -5~-8도, 시작은 잘려도 되지만 끝은 화면 안) / C 키워드(한 글자만 빨강 가능).
- 레퍼런스 애니메이션: 부르는 순간 글자가 획 조각부터 나타나 0.2초 안에 완성, 큰 글자는 글자마다 기준선/크기/기울기가 조금씩 다름, 퇴장은 글자별 시차로 희미해짐. 바운스 금지.
- 글자가 눈/얼굴을 가리면 안 됨. 밝은 배경 위 작은 가사는 짙은 글자.
- 한국어 자막: 하단 중앙, 작고 얇게, 페이드만. 후리가나 없음.

### 전환
- 빛번짐(8프레임, 사선 블러, 정점 거의 흰색), 블러 인아웃, 휩, 흰 번쩍임, 검은 화면 컷, 글리치 등. 같은 전환 연속 금지.
- 글리치는 곡 전체 3~4회, 각 0.2초 이하. 전환 중에도 가사는 사라지지 않게(화면이 하얘지면 글자를 어둡게).

## 자동 점검 (매 렌더 후 보고)
- 가사 40줄(전체) 각각 3개 시점: 글자-얼굴 겹침 0, 글자-배경 대비 60 이상.
- 같은 장면 type 연속 없음, 같은 전환 연속 없음, 글리치 횟수.
- 오디오 싱크 시작/중간/끝 오프셋 0ms.
- 무채색 / HUD / 가는 명조 / 크롭 클로즈업(전신 20% 이하) / 포인트 컬러 횟수.

## 기술 규칙
- 한 HTML 페이지, seek(t)가 t만으로 한 프레임을 그림(상태 없음). preview와 final은 해상도/fps/후처리만 다름.
- Playwright 병렬 렌더, 섹션별 청크, 재개 가능(manifest), 로그, 바뀐 섹션만 다시 렌더.
- 모션 블러는 final에서만(셔터 180도, 3샘플). 음수 시간 샘플 주의.
- 렌더/측정 파일은 커밋하지 말고(out/), 코드와 데이터는 단계마다 커밋·푸시.
